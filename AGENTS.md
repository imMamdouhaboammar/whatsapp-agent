# AGENTS.md

## Repository Overview & Philosophy
You are an autonomous engineering agent working in the `whatsapp-agent` codebase. This project powers a production-grade WhatsApp conversational AI copilot and autonomous moderator with real-time SSE streaming, production Supabase PostgreSQL persistence (with local SQLite developer caching), multi-model fallback, and a React + Lobe UI cockpit.

## Engineering Mandates

### 1. Root Cause Mode
Whenever investigating any bug, regression, crash, layout shift, or unexpected behavior:
- **Diagnose Before Fixing**: Always identify the underlying root cause before proposing or writing code changes.
- **Reproduce First**: Formulate a falsifiable test or minimal reproduction that proves the failure.
- **Separate Symptoms From Cause**: Superficial symptom patching without diagnosing underlying reasons is strictly forbidden.
- **Smallest Root Fix**: Implement the cleanest, most surgical fix at the canonical boundary.
- **Verification Proof**: Prove the fix with regression test execution (`bun test` and `bun test:ui`) before marking the issue resolved.
- **Preserve Existing Behavior**: Do not break existing regression suites; all pre-existing tests must remain green.

### 2. Package Manager & Runtime Integrity
- **Bun is Mandatory**: Every JavaScript and TypeScript operation (installing packages, running scripts, running tests, local dev) must use Bun (`bun`, `bunx`, `bun test`). Never invoke `npm` or `yarn`.
- **Zero Credentials in Memory**: Never persist passwords, API keys, tokens, or OTPs. All memory additions must pass Unicode-aware fail-closed regex screening.
- **Dynamic Secret Tokens in Test Fixtures**: Test fixtures asserting secret-scrubbing behavior must construct dummy tokens dynamically at runtime (e.g. `['sk', 'live', ...].join('-')`) rather than embedding static literal strings to prevent pre-commit (`BK-AI-SEC-001`) and CI scanner false positives.
- **Atomic Filesystem Access (No TOCTOU)**: Storage and memory helpers must avoid `fs.existsSync` pre-checks. Attempt reads/writes directly in a `try/catch` block handling `ENOENT` or error codes atomically.
- **WhatsApp Network Boundary**: Enforce a strict limit of 100 KB (101,888 bytes) on all generated WebP stickers.
- **Fail-Closed Model Fallback**: Fail immediately on 401/403 authentication errors. Never switch models on auth failures.

### 3. Install Agent Harness & Tooling Inventory
When selecting tools and skills for this project, adhere strictly to the harness governance rules:
- **Bulk Install Guard**: Only install what this project actually needs right now. Do not bulk install every available skill, as unnecessary context overhead degrades reasoning.
- **Harness Priority Matrix**:
  - `unslop-preflight` (Priority: Required) — Used before and during frontend modifications to prevent AI slop, audit design tokens, and enforce accessibility. Skip when working exclusively on backend database migrations.
  - `lobe-icons` (Priority: Required) — Used for rendering official AI provider logos and model badges in UI components. Skip when editing CLI tools.
  - `lobe-ui` (Priority: Required) — Used for accessible UI primitives (AgentAvatar, Tag, Badge, Avatar, ActionIcon, ConfigProvider). Skip when writing server routes.
  - `test-guard` (Priority: Recommended) — Enforces TDD red-green verification loops.
  - `clean-code-guard` (Priority: Recommended) — Enforces DRY, KISS, and modular code hygiene.
- **Trust & Verification Steps**: Always perform a version check, dry run, and source code review before adopting external harnesses. Verify dependencies and ensure rollback paths exist.

### 4. React & Code Review Harness Recommendations
- **React Runtime Safety**: Wrap component trees with a resilient React Error Boundary (`react-error-boundary`) and `ConfigProvider` to safeguard against rendering exceptions and runtime boundary failures.
- **Code Review & Duplication**: Maintain clean architectural boundaries between `src/domain` (business logic), `src/server` (HTTP API), `src/ai` (Gemini moderator & fallback), and `ui/src` (React cockpit). Regularly execute duplication scan and review graph checks to prevent copy-pasting styling or schema definitions.

### 5. Anti-Slop Interface Standards
- **Intentional Iconography**: Never use decorative floating stars or magic wands as lazy signifiers for AI functionality. Use precise semantic icons (`Bot`, `Settings`, `Sliders`, `Zap`, `Image`).
- **Vector Assets Only**: Never use casual pictograms as structural UI controls. Always use official vector SVGs from `@lobehub/icons`, `@lobehub/ui/icons`, or `lucide-react`.
- **Accessible Modals**: Every modal or drawer must declare `role="dialog"`, `aria-modal="true"`, trap keyboard focus, bind dismiss to the Escape key, and enforce internal scrolling (`overflow-y-auto`) within `max-height: min(90dvh, 720px)`.

### 6. Continuous Learning & Self-Correction Engine Mandates
- **Supabase PostgreSQL as Production Memory Tier**: In production Supabase SaaS environments, long-term memory states (`workbook.md` procedural rules, `notebook.md` semantic profiles, reflection runs, feedback events) MUST persist directly to Supabase PostgreSQL (`wa_agent.learning_states`), never local SQLite fallbacks. Local markdown files serve as a materialized local developer view.
- **Offline Reflection Latency Decoupling**: High-reasoning reflection loops (`gemini-4-argon` with thinking_config HIGH) must run completely offline (`ReflectionWorker`) after conversation threads go cold (15m inactivity threshold) or on explicit moderation actions. Inbound WhatsApp turns must answer in <2s with zero reflection latency.
- **Fail-Closed Unicode Credential Screening**: All additions to memory must pass Unicode-aware fail-closed regex screening (`scrubCredentials`) before disk or database commits to prevent sensitive customer data leakage.
- **Context Protection & Distillation**: Procedural memory (`workbook.md`) must trigger automatic distillation via `gemini-4-argon` when exceeding 15 rules or 2500 tokens, synthesizing sprawling rules into 5-8 bulletproof execution guardrails.

### 8. Application Security & Static Analysis Invariants (CodeQL / SAST)
- **Character Class Range Hygiene (CWE-20)**: When authoring regular expressions with dashes `-`, colons `:`, or pipes `|`, always escape hyphens (`\-`) or anchor them to the start/end of the character class (`[\s:|\-]`). Never write unescaped ranges like `[:-|]` which inadvertently span wide ASCII alphanumeric tables. Full details in [FL-007](./failure-lessons/007-codeql-regex-range-ascii-collision.md).
- **Atomic File Access Over TOCTOU Checks (CWE-367)**: Prohibit `existsSync(path)` checks immediately preceding `readFileSync` or `writeFileSync`. Read and write directly within guarded `try / catch` blocks checking `err.code === 'ENOENT'` to eliminate Time-of-Check to Time-of-Use race windows. Full details in [FL-008](./failure-lessons/008-file-system-race-condition-toctou.md).

### 11. DevSecOps & Polyglot Vulnerability Gates (GitHub Advisory Database & SCA)

### 12. Cloud Database & Supabase Infrastructure Mandates
- **Supabase IPv4 Pooler Discovery Invariant**: Never assume direct `db.<project-ref>.supabase.co` hostnames are IPv4-routable (they publish exclusively IPv6 AAAA records on free/standard tiers). Always discover the exact regional Supavisor pooler cluster index (`aws-[0-3]-[region].pooler.supabase.com`), configure dual-URL topologies (`DATABASE_URL` for IPv4 session pooler on port 5432, `DATABASE_TRANSACTION_URL` on port 6543, and `DATABASE_DIRECT_URL` for IPv6), and enforce tenant-prefixed usernames (`postgres.<project-ref>`). Full details in [FL-025](./failure-lessons/025-supabase-ipv6-routing-and-pooler-discovery.md).
- **Extension Schema Namespace Isolation Invariant**: Never apply a blanket `WITH SCHEMA extensions` target across all PostgreSQL extensions. Extensions with hardcoded internal namespaces (such as `pgmq`) MUST be preceded by explicit schema creation (`CREATE SCHEMA IF NOT EXISTS pgmq`) and installed with matching schema (`WITH SCHEMA pgmq`). Full details in [FL-027](./failure-lessons/027-postgresql-extension-schema-namespace-isolation.md).
- **Agent Kernel Vault & Permission Invariant**: When linking environment files to Agent Kernel vault, immediately enforce octal permissions `0600` (`chmod 600 .env ui/.env`) before pushing to prevent permission drift, and maintain third-party service account email bindings canonically in `~/.agent-kernel/service-accounts.json`. Full details in [FL-029](./failure-lessons/029-agent-kernel-vault-service-account-binding.md).
- **Multi-Org Token Decoupling Invariant**: Decouple local database migrations, runtime connections, and environment files from the host CLI's global OAuth token. Local project references must be declared on-disk in `supabase/.temp/project-ref`, and runtime connections must authenticate via direct pooler connection strings and secret keys. Full details in [FL-031](./failure-lessons/031-supabase-cli-multi-org-token-scope-collision.md).
