## Rules We Now Enforce

1. **Supabase PostgreSQL Invariant**: In production environments, long-term memory states (`workbook.md` procedural rules and `notebook.md` semantic profiles) must persist directly to PostgreSQL (`wa_agent.learning_states`), reserving local markdown files as a materialized developer view.
2. **Zero-Latency Inbound Invariant**: Inbound WhatsApp messages must never trigger synchronous LLM reflection. Fast path replies immediately (<2s) and commits raw turns to storage; reflection is executed asynchronously by an offline worker when threads become cold (15m inactivity).
3. **Fail-Closed Unicode Credential Invariant**: All memory additions must pass Unicode-aware fail-closed regex screening (`scrubCredentials`) before disk or database commits.
4. **Context Budget Compaction Invariant**: When procedural rules exceed safety limits (15 rules or 2500 tokens), the system must trigger LLM distillation to consolidate verbose logs into dense, actionable guardrails.
5. **Permissive Inbound Controller Invariant**: REST endpoints receiving human operator revisions must accept standard synonyms (`editedText` and `replyText`) to prevent dropped feedback events.
6. **Dynamic Secret Token Invariant**: Test fixtures asserting secret-scrubbing or credential-sanitization behavior MUST construct token patterns dynamically at runtime (e.g. `['sk', 'live', ...].join('-')`) rather than embedding static literal secret strings that trigger pre-commit and CI secret scanning gates (`BK-AI-SEC-001`).
7. **Atomic Filesystem Invariant (No TOCTOU)**: File system read/write operations must avoid `fs.existsSync` pre-checks. Always attempt the operation directly inside a `try/catch` and handle `ENOENT` or error codes explicitly.
8. **Cell-by-Cell Table Delimiter Invariant**: Markdown table separator detectors must validate every parsed cell individually (`/^:?-+:?$/`) rather than applying line-level fuzzy regex, and regex patterns must avoid unnecessary escapes (`no-useless-escape`).
9. **Mutation-Evidence Synchronization Invariant**: In get-fable projects, before pushing to remote, always record fresh passing verification evidence via `get-fable evidence pass` to advance `verifiedGeneration` to match `mutationGeneration`.
10. **Stderr Banner Invariant**: Agent lifecycle hooks, ambient monitors, and CLI wrappers must direct informational and diagnostic banners strictly to `stderr`, never `stdout`, to guarantee stream purity during shell redirection and piping.
11. **Git Remote Tracking Pruning Invariant**: After remote PR merges, always ensure the local working tree is clean before switching branches, and execute `git fetch --prune origin` to purge deleted remote-tracking references.
12. **Hermetic Build Sandboxing**: Genrules and toolchains in Buck2 must dynamically resolve paths without relying on hardcoded directories or `$(pwd)`.
13. **CSS Layer Priority Invariant**: External design system resets must load inside CSS `@layer` or `@scope` so unlayered consumer variables (`--wa-*`), Tailwind utilities, and Arabic RTL layouts (`dir="rtl"`) maintain precedence.
14. **Monorepo Single React Instance Invariant**: All frontend SSR tests and build scripts must execute inside the workspace directory (`ui/`) using Bun to prevent duplicate hoisted React runtime instances.
15. **Git Branch History Secret Cleanliness Invariant**: Security scanners evaluate every commit in a PR branch (`main..HEAD`). Fixing a leaked credential in a subsequent commit fails secret scanning gates; branches with leaked credentials must be interactively squashed/rebased so the credential was never committed. Fallback values in code must never contain credentials.
16. **Resilient Transport & Event Invariant**: Frontend HTTP clients must check `res.ok` before attempting `res.json()`, and all Server-Sent Event (SSE) decoders must be fenced with `try/catch` handlers to prevent tab-crashing on malformed payloads.
17. **Authoritative Action SHA Invariant**: Pinned third-party GitHub Actions must use verified 40-character commit hashes resolved directly from upstream remotes (`git ls-remote`), and CI test steps must explicitly install dependencies (`bun install`) in fresh runner environments.
18. **Git Index Regular File Invariant**: Staged Git commits must contain strictly regular files and directories. Never stage filesystem symbolic links (e.g., from `npx skills add`); local toolchain state folders (`.agents/`, `.claude/`) must remain in `.gitignore`.
19. **Polyglot Monorepo SCA Invariant**: In Bun-based repositories where `npm`/`yarn` are prohibited, dependency scanning across JavaScript/TypeScript and Python workspaces must utilize `osv-scanner` (powered by GitHub Advisory Database / OSV schema) and `pip-audit`. Transitive advisories in upstream packages must be patched via `"overrides"` in `package.json`.
20. **Two-Step Lifecycle State Transition Invariant**: In `get-fable` workspaces, direct jumps from `executing` to `complete` are prohibited. Agents must first transition to `verifying`, record passing typed evidence (`get-fable evidence pass`) to synchronize `verifiedGeneration` with `mutationGeneration`, and only then transition to `complete`.
21. **Supabase IPv4 Pooler Discovery Invariant**: Never assume direct `db.<project-ref>.supabase.co` hosts are IPv4-routable (they publish exclusively IPv6 AAAA records on free/standard tiers). Always discover the exact regional Supavisor pooler cluster index (`aws-[0-3]-[region].pooler.supabase.com`), configure dual-URL topologies (`DATABASE_URL` for IPv4 session pooler on port 5432, `DATABASE_TRANSACTION_URL` on port 6543, and `DATABASE_DIRECT_URL` for IPv6), and enforce tenant-prefixed usernames (`postgres.<project-ref>`).
22. **Extension Schema Namespace Isolation Invariant**: Never apply a blanket `WITH SCHEMA extensions` target across all PostgreSQL extensions. Extensions with hardcoded internal namespaces (such as `pgmq`) MUST be preceded by explicit schema creation (`CREATE SCHEMA IF NOT EXISTS pgmq`) and installed with matching schema (`WITH SCHEMA pgmq`).
23. **Vault Permission & Service Account Invariant**: When binding environment files to Agent Kernel vault, immediately enforce octal permissions `0600` (`chmod 600 .env ui/.env`) before pushing to prevent permission drift, and maintain third-party service account email bindings canonically in `~/.agent-kernel/service-accounts.json`.
24. **Multi-Org Token Decoupling Invariant**: Decouple local database migrations, runtime connections, and environment files from the host CLI's global OAuth token. Local project references must be declared on-disk in `supabase/.temp/project-ref`, and runtime connections must authenticate via direct pooler connection strings and secret keys.
25. **TruffleHog Event Ref Invariant**: In GitHub Actions secret scanning workflows, always fetch full repository history (`fetch-depth: 0`). For `push` events, never set `base: ${{ github.ref_name }}` alongside `head: HEAD` as it forces a fatal `BASE == HEAD` runtime collision; omit `base` on push to scan newly pushed commits automatically (`base: ${{ github.event_name == 'pull_request' && github.base_ref || '' }}`). Synthetic test tokens must be excluded via `.trufflehog-exclude` and `--only-verified`.
26. **Non-Interactive Linter Invariant**: CLI linters and code health tools executed by autonomous agents or background tasks (e.g. `qlty check`) must explicitly disable interactive formatting prompts via `--no-formatters` or `--fix=false`. External agent skill libraries (`.agents/**`, `.claude/**`, `.unslop/**`) and vendor assets must be excluded from static analysis engines via `exclude_patterns`.
27. **CI Action Authentication & MCP Resiliency Invariant**: Third-party GitHub Actions requiring authentication (e.g. `sourcery-ai/action@v1`) must guard executions with `continue-on-error: true` when repository secrets (`SOURCERY_TOKEN`) may not yet be configured across all forks or environments. When configuring remote MCP endpoints with Bearer tokens across different agent runtimes, use native configuration schemas (`headers.Authorization` for Antigravity/Gemini, HTTP transport flags for Claude, and `bearer_token_env_var` for Codex).
28. **SonarQube LCOV Coverage Invariant**: SonarQube Cloud workflows must trigger on both `main` and `master` branches, and code coverage must be generated via Bun's native LCOV reporter (`bun test --coverage --coverage-reporter=lcov --coverage-dir=coverage`) matching `-Dsonar.javascript.lcov.reportPaths=coverage/lcov.info` without invoking extraneous test packages.
29. **PR Mergeability & Webhook Isolation Invariant**: Distinguish between actual PR mergeability (`mergeable: "MERGEABLE"`) and advisory status checks (`mergeStateStatus: "UNSTABLE"`). When optional third-party integrations (e.g. disconnected deployment targets) fail but core CI and branch protection rules pass, verify the full test pyramid locally in a dedicated worktree and merge with authoritative evidence rather than blocking delivery.
30. **Motion Context Provider Invariant (FL-032)**: Any React component tree utilizing `@lobehub/ui` MUST provide an explicit `motion` instance through `<ConfigProvider motion={motion}>` or `<MotionProvider motion={motion}>` at the foundational provider boundary, ensuring headless SSR test harnesses and client routes share identical animation runtime context.
31. **Quarantined Tooling Invariant (FL-033)**: External agent skills, testing harnesses, and auxiliary developer tooling containing internal test suites MUST NEVER be checked out into visible root directories (`skills/`, `tools/`). They must strictly reside in dot-prefixed paths (`.agents/skills/`, `.claude/skills/`, `.gemini/config/skills/`) or be installed as scoped node modules to prevent test runner discovery contamination.
32. **Domain-Positive Governance Invariant (FL-034)**: In policy and governance documents evaluated by static regex linters, express standards using domain-positive assertions rather than repeating forbidden words in negative phrases. Avoid CSS arbitrary bracket syntax (`[...]`) in markdown prose to prevent false collisions with template placeholder scanners.
33. **Zero-Unused-Locals Invariant (FL-035)**: In TypeScript projects with `noUnusedLocals: true`, never introduce speculative imports without immediate DOM or logical integration. All UI component refactoring must be verified with `cd ui && bun run build` to ensure complete absence of TS6133 errors before handoff.
34. **Dual-Topology CI Invariant (FL-036)**: When introducing self-hosted or ephemeral runners (such as `runner-up`) to accelerate CI pipelines, always maintain an automated cloud fallback (`ubuntu-latest`) or dual matrix configuration so external PRs and offline states never block the repository quality gates.
35. **Bounded Asynchronous Task Invariant (FL-037)**: All asynchronous workers, background queues, and concurrent loops must declare explicit upper bounds on concurrency and exponential backoff on retries. Long-running tasks must emit structured telemetry with contextual error classification.
36. **Transport Lifecycle & Fail-Closed Session Invariant (FL-038)**: Authentication and session guards must fail-closed on unknown or malformed tokens, rejecting insecure fallbacks. Network reconnect loops must enforce jittered backoff and maximum retry thresholds.
37. **Impeccable UI/UX, Anti-Slop & Accessibility Invariants (FL-039)**:
    - *Flat Pill Hierarchy*: Prohibit nesting bordered or colored card containers inside drawer/card sections for button groups; use flat unboxed pill rows.
    - *Accessibility Text Floor & WCAG AA Contrast*: All functional UI text must be $\ge 11\text{px}$ across all responsive breakpoints; continuous body text must be $\ge 12\text{px}$; all foreground/background pairings must pass mathematical contrast ratio $\ge 4.5:1$ (WCAG AA).
    - *Composite-Only Animation & Single-Pixel Accents*: Animations must never target `width`, `height`, `padding`, or `margin`; third-party CSS classes with `transition: padding` must be neutralized via unlayered CSS overrides; side-tab border accents must not exceed `1px`.
    - *Popover Containment Over Clipping*: Root application shells must use `overflow: clip; position: relative` rather than `overflow: hidden` to allow positioned popovers, reaction chips, and floating toolbars to render without layout clipping.
35. **Anti-Slop SRE & Concurrency Invariant (FL-037)**: All asynchronous bulk tasks (embeddings, web scrapers, document conversions) must be bounded with chunked batches (`batchSize = 10`), exponential reconnection backoffs must incorporate full uniform random jitter, and ephemeral promise queues must evict keys upon settlement (`.finally(() => sendQueues.delete(chatId))`).
36. **Transport Lifecycle & Fail-Closed Invariant (FL-038)**: Socket disconnects must be guarded by `isExplicitlyClosed` with tracked and cleared backoff timers to prevent Baileys 440/515 session collisions; dashboard auth must exempt signed webhook and internal scatter-gather prefixes; generated WhatsApp WebP stickers must strictly respect the 100 KB limit (101,888 bytes) and 512x512 geometry; LLM HTTP clients must buffer response text first to preserve HTTP status codes for fallback engines; and security registries must fail closed when zero keys are configured.
37. **Impeccable UI/UX Quality & Accessibility Invariant (FL-039)**: All modals and drawers must declare `role="dialog"` and `aria-modal="true"`, capture and restore focus, trap keyboard navigation, bind Escape dismissal to `useModalDismiss`, and enforce strict contrast ratios without generic AI aesthetic tropes.
38. **Zero Platform Sprawl & Root Configuration Invariant (FL-040)**: Project repositories must maintain strictly one canonical agent constitution (`AGENTS.md`). Committing speculative, copy-pasted configuration folders or prompt stubs for unused third-party AI platforms (`.amazonq`, `.continue`, `.cursor`, `.devin`, `.junie`, `.kilo`, `.openhands`, `.plandex`, `.qodo`, `.trae`, `.aider.prompt.md`, `.clinerules`, `.roomodes`, `.windsurfrules`) is prohibited AI slop.
